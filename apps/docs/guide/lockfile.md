# Lock-файл

`bapm.lock.yaml` фиксирует, что именно установлено: коммит каждого пакета, пути развёрнутых файлов и их хеши. С ним у всей команды и в CI ставятся одни и те же версии, даже если в манифесте указана ветка вроде `main`.

Коммитьте `bapm.lock.yaml` вместе с `bapm.yml`. Руками его не правьте: bapm перезаписывает его сам.

## Какие команды меняют lock

| Команда                 | Что делает с lock                                                                              |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `bapm install`          | Создаёт lock или дописывает новые пакеты; закреплённые версии не трогает                       |
| `bapm install --frozen` | Не меняет; падает, если lock нет, у прямой зависимости нет пина или развёрнутые файлы изменены |
| `bapm update`           | Переразрешает ветки и диапазоны версий, записывает новые коммиты                               |
| `bapm install --update` | То же, что `update`, и сразу раскладывает файлы                                                |
| `bapm lock`             | Создаёт или обновляет lock без раскладки файлов агенту                                         |
| `bapm outdated`         | Только показывает, где есть обновления                                                         |

`--force` не обновляет версии: для этого нужен `update`.

Смену `#ref` у уже закреплённого пакета (`#v1` → `#v2`) frozen считает расхождением: install падает с `Frozen install ref drift`, пока lock не обновлён обычным `bapm install --update` или `bapm update`. После такой правки закоммитьте обновлённый `bapm.lock.yaml`.

## Форматы хешей

Алгоритм во всех хеш-полях один — SHA-256, но записываются они по-разному:

| Поле                                                       | Формат в lock                                 |
| ---------------------------------------------------------- | --------------------------------------------- |
| `resolved_hash`, `tree_sha256`, `source_digest`            | `sha256:<hex>` (envelope, lowercase hex)      |
| `deployed_file_hashes` при свежей раскладке `bapm install` | `<hex>` без префикса (lowercase hex)          |
| `deployed_file_hashes` после загрузки и перезаписи lock    | `sha256:<hex>`: `bapm lock` нормализует карту |

Это разные поля, а не только разные форматы: не сравнивайте строки из `deployed_file_hashes` с `tree_sha256` или `resolved_hash` напрямую. bapm принимает оба вида при чтении и проверке, но внешние скрипты и ручной diff должны нормализовать `sha256:` и голый hex.

Если `bapm lock` загружает существующий lock, карта `deployed_file_hashes` нормализуется и при записи остаётся в виде `sha256:<hex>` — формат может измениться без изменения содержимого файлов.

## В CI

Если переменная окружения `CI` задана (и не равна `""`, `0`, `false`), `bapm install` сам работает как `--frozen`. Отключить: `--no-frozen`. Совмещать frozen с `--update` нельзя.

Пошагово: [CI по lock-файлу](/guide/situations/ci-frozen).

## Версии схемы

bapm читает и пишет `lockfile_version: "1"` и `"2"`. Версия `"3"` появилась в APM 0.35 для root-правил `replace:` (секция `replacements:` и per-dependency `replacement:`). bapm не реализует replacement: такой lock отвергается с `LOCKFILE_V3_UNSUPPORTED`, а манифест с непустым `replace:` — с `MANIFEST_REPLACE_UNSUPPORTED`, чтобы не установить upstream вместо настроенного fork/local checkout. Уберите `replace:` и перегенерируйте lock командой `bapm lock` либо используйте для этого проекта APM 0.35+.

## Immutable literal refs

Если два ребра графа требуют один и тот же пакет с разными literal `git` + `ref`, bapm не выбирает одно из них молча. Resolve сверяет коммиты: разные имена ref допустимы, только если они указывают на один коммит; иначе установка падает с `RESOLVE_IMMUTABLE_CONFLICT` и печатает обе цепочки, оба ref и оба коммита. Приведите refs в манифестах к одному коммиту и перегенерируйте lock. Semver-диапазоны по-прежнему разрешаются через intersection-pick.

## Расширения зависимости в lock

Верхнеуровневые `x-*` поля манифеста зависимости копируются в строку lock как `extensions` (APM-поле). Если расширений нет, поле не пишется. Значения не интерпретируются; поле сохраняется при чтении и перезаписи lock.

```yaml
- repo_url: github.com/acme/tools
  resolved_commit: "…"
  extensions:
    x-acme-owner: platform
```

## Локальные записи в lock

Для пакетов с источником `local` / `path:` bapm пишет строку, совместимую по полям с APM 0.35, но сохраняет свои прежние alias-поля:

| Поле               | Значение                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------- |
| `repo_url`         | bapm-alias `local:<путь от корня>` (пока не `_local/<name>`)                                            |
| `path`             | bapm-alias: путь от корня проекта в POSIX-виде                                                          |
| `local_path`       | APM-поле: для прямой зависимости совпадает с `path`, для транзитивной — относительно объявившего пакета |
| `declaring_parent` | имя пакета, объявившего зависимость (из цепочки `resolved_by`)                                          |
| `resolved_by`      | цепочка объявления `root->parent->pkg`                                                                  |
| `depth`            | глубина в графе зависимостей                                                                            |
| `package_type`     | `local`                                                                                                 |
| `content_hash`     | `sha256:<hex>` — канонический tree hash содержимого локального пакета                                   |
| `is_dev`           | только если значение известно из ранее прочитанного APM-lock                                            |

`content_hash` совпадает с APM по форме поля (`sha256:<hex>`), но bapm считает его своим каноническим tree hash. Не сравнивайте его побайтно с `content_hash`, записанным APM: алгоритмы обхода дерева различаются. Практическая польза — фиксировать изменение содержимого локального пакета между генерациями lock.

bapm читает и локальные записи APM: `repo_url: _local/<name>` вместе с `local_path` распознаётся как local-источник (даже если `source` отсутствует), сопоставляется с текущим пакетом по `local_path`/имени и не теряется при перезаписи lock. При перезаписи bapm пока сохраняет свой `repo_url: local:<путь>`; полный переход на `_local/<name>` — отдельное изменение.

## Личный lock: `bapm.local.lock.yaml`

Появляется, только если в манифесте есть зависимости с источником `local` — личные пакеты, которые есть только на вашей машине. Их версии пишутся в отдельный файл, чтобы не попадать в общий lock и в чужие PR.

- bapm сам добавляет `bapm.local.lock.yaml` в `.gitignore`.
- Когда последняя `local`-зависимость убрана, файл удаляется.
- При чтении bapm объединяет оба lock-файла.
- Записи `path: ./…` — это общие пакеты, они остаются в `bapm.lock.yaml`. В lock путь хранится относительно корня проекта, поэтому файл переносим между машинами.

Зачем и как: [Личные пакеты](/guide/situations/personal-local-lock).

## Имена файлов

| Файл                   | Когда используется                                                           |
| ---------------------- | ---------------------------------------------------------------------------- |
| `bapm.lock.yaml`       | По умолчанию                                                                 |
| `apm.lock.yaml`        | Если в проекте уже есть lock от microsoft/apm — bapm продолжит писать в него |
| `bapm.local.lock.yaml` | Личный lock                                                                  |

Держите только один из `bapm.lock.yaml` и `apm.lock.yaml`: если есть оба, команды завершатся ошибкой `Both apm.lock.yaml and bapm.lock.yaml are present`. `apm.local.lock.yaml` не поддерживается.

## Экспорт SBOM

```bash
bapm lock export -f cyclonedx -o sbom.json
```

Форматы: `cyclonedx` и `spdx`. Подробнее: [lock](/reference/lock#lock-export).

## Частые ошибки

| Сообщение                                             | Что делать                                                                                                                                                                                |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Frozen install requires an existing lockfile`        | Выполните `bapm install` локально и закоммитьте `bapm.lock.yaml`                                                                                                                          |
| `Both apm.lock.yaml and bapm.lock.yaml are present`   | Удалите один из файлов. Совет `Pass an explicit path` из сообщения не поможет: такого флага нет                                                                                           |
| `Unsupported personal lock brand apm.local.lock.yaml` | Удалите `apm.local.lock.yaml`                                                                                                                                                             |
| `Lock identity conflict between … and …`              | Один пакет записан и в общем, и в личном lock с разными пинами. `bapm lock` это не исправит: удалите запись из одного файла (обычно из `bapm.local.lock.yaml`) и выполните `bapm install` |
| `bapm doctor`: `local-lock … is git-tracked`          | `git rm --cached bapm.local.lock.yaml`                                                                                                                                                    |

::: warning Секреты из старых версий
MCP-серверы записываются в lock с `${VAR}`, без подставленных значений. Ранние версии bapm записывали туда и значения: если такой lock закоммичен, выполните `bapm install` и смените токены. Подробнее: [MCP и переменные окружения](/guide/manifest-dependencies#mcp-и-переменные-окружения).
:::
