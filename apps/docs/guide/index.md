# Как работает bapm

Эта страница объясняет несколько понятий, на которых построена остальная документация. Если хотите сразу попробовать, откройте [Быстрый старт](/guide/quick-start).

## Файлы проекта

| Файл                   | Что в нём                                                             | В git |
| ---------------------- | --------------------------------------------------------------------- | ----- |
| `bapm.yml`             | Манифест: какие пакеты и MCP-серверы нужны проекту                    | да    |
| `bapm.lock.yaml`       | Lock: точные коммиты и хеши установленных файлов                      | да    |
| `bapm.local.yml`       | Личные настройки: ваш агент, ваши значения переменных                 | нет   |
| `bapm.local.lock.yaml` | Lock для личных пакетов из `.agents/local` (появляется только с ними) | нет   |
| `apm_modules/`         | Скачанные пакеты                                                      | нет   |

Вместо `bapm.yml` и `bapm.lock.yaml` можно использовать `apm.yml` и `apm.lock.yaml` из microsoft/apm: bapm их читает. Держите в проекте только один из вариантов: если лежат оба манифеста или оба lock-файла, команды завершаются ошибкой. bapm ищет эти файлы только в текущем каталоге, в родительских не ищет.

## Пакет

Пакет — каталог (обычно git-репозиторий или его подкаталог) со своим `bapm.yml` или `apm.yml` (`name` и `version`) и файлами для агента. bapm находит их по раскладке APM:

| Что                           | Где в пакете                                                     |
| ----------------------------- | ---------------------------------------------------------------- |
| skills                        | `skills/<name>/SKILL.md`, `.apm/skills/`, или `SKILL.md` в корне |
| instructions (rules у Cursor) | `.apm/instructions/`                                             |
| agents (субагенты)            | `.apm/agents/`                                                   |
| commands                      | `.apm/prompts/<name>.prompt.md` или `<name>.prompt.md` в корне   |
| hooks                         | `.apm/hooks/*.json` или `hooks/*.json`                           |
| MCP-серверы                   | `dependencies.mcp` в манифесте пакета                            |

Каталоги `rules/` и `commands/` в корне пакета bapm не читает.

Пакет берётся из GitHub (`org/repo`), любого git-URL, локального пути или, экспериментально, из registry. Формы записи: [Зависимости](/guide/manifest-dependencies).

## Агент и интеграция

bapm не знает заранее, какой у вас агент. Поддержка каждого агента — отдельный npm-пакет-интеграция:

```bash
npm i -D @b-apm/cli @b-apm/integration-cursor
```

Интеграция знает, куда класть файлы: для Cursor skills уходят в `.agents/skills/`, rules в `.cursor/rules/`, MCP в `.cursor/mcp.json`. Для Claude Code — в `.claude/` и `.mcp.json`. Список агентов и путей: [Поддерживаемые агенты](/guide/supported-hosts).

В CLI и манифесте агент называется **target** (или host), а его идентификатор — `cursor`, `claude`, `codex` и т. д. Отсюда флаг `--target cursor`.

Если агент не поддерживает какой-то тип файлов (например, hooks), bapm его пропускает. Сейчас install об этом не сообщает; что поддерживает каждый агент, смотрите в [таблице](/guide/supported-hosts#skipped).

## Как bapm выбирает агента

По порядку, первое сработавшее правило побеждает:

1. флаг `--target <id>`;
2. поле `active` в `bapm.local.yml`;
3. поле `active` в `bapm.yml`;
4. автоопределение: маркер в каталоге (`.cursor/`, `.claude/`, `.codex/`…) узнала ровно одна из установленных интеграций.

В `active` можно указать несколько агентов: install разложит файлы для каждого. Если ничего не сработало или автоопределение нашло несколько агентов, `install` останавливается и просит указать `--target`. Подробнее: [Выбор агента](/guide/host-selection).

## Что делает `bapm install`

1. Читает `bapm.yml` (и `bapm.local.yml`, если есть).
2. Разрешает зависимости и проверяет их по политике проекта; при нарушении install останавливается, ничего не записав.
3. Скачивает пакеты в `apm_modules/` и пишет lock.
4. Раскладывает файлы в каталоги выбранных агентов.

`bapm lock` делает первые три шага, без раскладки. `bapm compile` отдельно собирает сводный файл вроде `AGENTS.md` для агентов, которые его читают.
