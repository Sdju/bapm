# bapm

bapm — менеджер пакетов для конфигурации AI-агентов. Skills, rules, описания агентов и MCP-серверы, которые обычно копируют между проектами вручную, объявляются в `bapm.yml` и ставятся одной командой:

```bash
bapm install
```

bapm скачивает пакеты, фиксирует версии в `bapm.lock.yaml` и раскладывает файлы туда, где их читает ваш агент: для Cursor это `.agents/skills/`, `.cursor/rules/`, `.cursor/mcp.json` и соседние каталоги.

::: warning Ранний релиз
Пакеты опубликованы на npm, но формат файлов и поведение команд ещё могут меняться без смены major-версии. Большая часть кода перенесена из [microsoft/apm](https://github.com/microsoft/apm) с помощью AI и пока не прошла полноценное ревью. Не используйте bapm там, где поломка конфигурации агента недопустима.
:::

## Что это даёт

- **Одинаковый агент у всей команды.** Набор skills и MCP хранится в git рядом с кодом, версии закреплены lock-файлом. Новый участник запускает `bapm install` и получает ту же конфигурацию.
- **Командное и личное — раздельно.** Общий `bapm.yml` описывает, что нужно проекту; личный `bapm.local.yml` (не в git) выбирает ваш агент и ваши значения переменных.
- **Несколько агентов на одном проекте.** Один манифест можно ставить в Cursor, Claude Code, Codex, Copilot и другие: каждый получает файлы в своём формате. То, что агент не поддерживает, пропускается, а не подменяется чем-то похожим; [что пропускает каждый агент](/guide/supported-hosts#skipped).
- **Воспроизводимый CI.** `bapm install --frozen` ставит ровно то, что записано в lock, и падает при расхождении.
- **Контроль над MCP.** Серверы из транзитивных зависимостей не ставятся без явного флага, а политика проекта и личные `approve` / `deny` решают, какие исполняемые пакеты допустимы.

## Отличия от microsoft/apm

bapm читает тот же формат манифеста (`apm.yml` тоже поддерживается) и совместим с OpenAPM v0.1, но это не копия APM CLI:

- поддержка агентов вынесена в отдельные пакеты `@b-apm/integration-*`, и можно подключить собственную интеграцию;
- есть личный слой настроек (`bapm.local.yml`) и личный lock для локальных пакетов;
- есть пресеты — именованные наборы зависимостей, которые включаются через `active`.

Подробнее о границах совместимости: [Совместимость с APM и OpenAPM](/guide/conformance).
