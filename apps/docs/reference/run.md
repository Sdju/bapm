# bapm run / bapm preview — скрипты проекта

`run` и `preview` выполняют команды из секции `scripts:` манифеста `bapm.yml` (или `apm.yml`). Это npm-подобные скрипты: они запускаются системным shell в каталоге проекта.

```yaml
name: my-project
version: 0.1.0

scripts:
  start: "echo hello"
  test: "node --test"
  greet: "echo hello {{name}}"
```

## Использование

```text
bapm run [SCRIPT] [-p name=value]... [-v] [--dry-run]
bapm preview [SCRIPT] [-p name=value]... [-v]
```

| Аргумент / флаг   | Значение                                           |
| ----------------- | -------------------------------------------------- |
| `SCRIPT`          | Имя скрипта; по умолчанию `start`                  |
| `-p, --param k=v` | Параметр; можно повторять                          |
| `-v, --verbose`   | Показать resolved-команду, cwd и имена параметров  |
| `--dry-run`       | Только `run`: напечатать команду и не выполнять её |
| `-h, --help`      | Показать help                                      |

Если имя не указано, используется `start`. Если `start` нет, команда завершается с ненулевым кодом и печатает список доступных скриптов. Неизвестный скрипт, неизвестный флаг и ошибка формата `name=value` тоже завершаются с ненулевым кодом.

## Параметры

Параметры подставляются в команду двумя синтаксисами:

- `{{name}}`
- `${input:name}` — совместимость с плейсхолдерами APM prompt-компилятора

```bash
bapm run greet -p name=World
# выполняет: echo hello 'World'

bapm preview greet -p name=World
# script: greet
# original: echo hello {{name}}
# resolved: echo hello 'World'
# parameters: name=World
```

Каждый параметр также экспортируется в окружение команды как `PARAM_<ИМЯ>` в верхнем регистре:

```yaml
scripts:
  show-env: "echo $PARAM_NAME"
```

```bash
bapm run show-env -p name=World
# World
```

Имена параметров должны быть env-safe: `[A-Za-z_][A-Za-z0-9_]*`. Значение может быть пустым (`name=`).

Неподставленные плейсхолдеры остаются как есть — это позволяет заметить опечатку в имени параметра. Плейсхолдеры лучше ставить отдельными токенами, а не внутри shell-кавычек:

```yaml
scripts:
  good: "echo {{name}}"
  bad: 'echo "hello {{name}}"' # кавычки вокруг плейсхолдера не нужны
```

## Preview и dry-run

`bapm preview` ничего не выполняет: печатает исходную команду, resolved-команду с уже подставленными и shell-экранированными значениями, а также список параметров.

`bapm run --dry-run` делает то же самое для команды `run`. Это удобно, чтобы проверить подстановку перед запуском.

## Коды выхода

| Ситуация                                  | Exit code                 |
| ----------------------------------------- | ------------------------- |
| Успех                                     | `0`                       |
| Нет манифеста / нет скрипта / нет `start` | `1`                       |
| Ошибка флагов или `name=value`            | `1`                       |
| Команда завершилась с ошибкой             | код команды (минимум `1`) |
| Preview или `run --dry-run` без ошибок    | `0`                       |

## Безопасность

> Скрипты выполняются с правами вашего пользователя через системный shell в каталоге проекта. Запускайте только те манифесты, которым доверяете.

bapm не использует `eval` для пользовательского ввода. Значения параметров экранируются как shell-литералы (одинарные кавычки в POSIX shell) до подстановки в команду. Поэтому значение вида `; rm -rf .` или `$(touch PWNED)` остаётся текстом аргумента и не выполняется как отдельная команда.

Ограничения:

- подстановка рассчитана на плейсхолдеры отдельными токенами; не вставляйте `{{name}}` внутрь уже существующих кавычек;
- сам текст скрипта — это доверенная конфигурация проекта, а не sandbox;
- `run` и `preview` не ходят в сеть и не меняют манифест, lock или файлы агентов;
- пароли и токены лучше не передавать через `-p`: они остаются в истории shell и могут попасть в verbose-вывод.

## Совместимость с APM

Поверхность повторяет базовое поведение APM 0.35: `run`/`preview`, default `start`, повторяемый `-p name=value`, список доступных скриптов и ненулевой код при ошибке. Prompt-компилятор APM (`.prompt.md` / `.apm/compiled`) в bapm пока не реализован: `run` выполняет команду из `scripts:` как есть, с подстановкой параметров.
