# `deny` не убирает уже записанный сервер

**Статус:** открыто  
**Класс:** продукт

## Суть

`bapm deny pkg` пишет запрет в `~/.bapm/config.json`. Следующий install не задеплоит MCP пакета. Строка, уже лежащая в `.cursor/mcp.json`, не удаляется.

## Состояние

| Источник       | Позиция                                                                                                                                 |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| APM            | Интерактивный deny ближе к «больше не предлагать»; уже записанный конфиг хоста часто остаётся.                                          |
| OpenAPM sc-010 | Deny — user-local, не обязан патчить host JSON.                                                                                         |
| Спека bapm     | Install withhold; нет требования синхронно вычищать конфиг.                                                                             |
| Код bapm       | `runDeny` / trust store. `configureMcp` пишет актуальный набор; если цикл MCP оборван или хост мержит JSON, старый сервер может выжить. |
| Документация   | `policy-mcp.md`: «удалите его оттуда вручную».                                                                                          |

## Вариации

1. Переписать конфиг агента без запрещённых серверов.
2. Только не добавлять новые (текущее + ручная чистка).
3. Отдельная команда `bapm mcp prune`.

## Поведение сейчас

После deny нужен ручной edit конфига агента. Вместе с [mcp-first-agent-only.md](./mcp-first-agent-only.md) второй агент и так не обновлялся.
