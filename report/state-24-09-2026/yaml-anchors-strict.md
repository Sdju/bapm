# YAML-якоря

**Статус:** намеренно  
**Класс:** намеренное отличие

## Суть

OpenAPM требует безопасное подмножество YAML. APM принимает более широкий набор, включая якоря, которые bapm отвергает.

## Состояние

| Источник     | Позиция                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------- |
| APM          | Более свободный YAML; якоря и алиасы на практике проходят.                                  |
| OpenAPM      | Строгий subset: якоря, которые дают общий объект на две записи, запрещены.                  |
| Спека bapm   | Parse/serialize fail-closed на запрещённых якорях (в т.ч. lock MCP configs).                |
| Код bapm     | Комментарий в `Mcp/lockInventory.ts`: массив `servers` копируется, чтобы не получить якорь. |
| Документация | `guide/conformance.md`: «YAML-якоря обрабатываются строго по OpenAPM».                      |

## Вариации

1. Принять якоря как APM — lock/манифест от APM с якорями заработает.
2. Отвергать как OpenAPM (текущий выбор).
3. Разыменовывать якоря при чтении и писать без них — не сделано.

## Поведение сейчас

Манифест или lock с запрещёнными якорями не загрузится. bapm сам якоря не пишет.
