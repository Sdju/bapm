# YAML-якоря

**Статус:** намеренно  
**Класс:** намеренное отличие  
**Важность:** низкая — жёсткий отказ вместо тихого принятия, но якоря в манифестах и lock редки, а обход простой: развернуть их в обычный YAML.  
**Проверено:** 08-11-2026, working tree

## Суть

OpenAPM требует безопасное подмножество YAML: якоря (`&`), алиасы (`*`) и нестандартные теги запрещены (`req-mf-020`). APM использует более свободный SafeLoader с бюджетом раскрытия и на практике принимает якоря. bapm реализует строгий вариант: один общий загрузчик проверяет весь документ и падает при первом же якоре, алиасе или кастомном теге (`packages/core/src/common/yaml/loadDocument.ts:36-70`).

Запрет строже, чем «якорь, который разделяет объект между записями»: отвергается **любой** `&anchor`, даже если `*alias` нигде не используется, и любой `*alias` без якоря. Проверка идёт на загрузке, а не на сериализации: манифест (`Manifest/load.ts:33`), личный оверлей (`Manifest/localOverlay.ts:68`) и lock (`Lockfile/parse.ts:15`) используют один и тот же safe-subset loader. Ошибка маппится в `MANIFEST_YAML_SAFE_SUBSET` / `LOCKFILE_YAML_SAFE_SUBSET`.

На записи bapm якоря не создаёт. В MCP-инвентаре lock массивы `servers` намеренно копируются, чтобы две ссылки не дали общий объект и YAML-якорь (`packages/core/src/modules/Mcp/lockInventory.ts:60-61`). То есть сериализатор не «отвергает» якоря — он их не порождает; fail-closed относится к чтению.

## Влияние

- **Сценарий:** миграция с APM, где `apm.yml` или `apm.lock.yaml` использует `&defaults` / `*defaults` для повторяющихся блоков.
- **Кого задевает:** команда при переходе на bapm; CI, который читает общий lock.
- **Последствие:** файл не загружается целиком, install завершается ошибкой до любых изменений; частичного применения нет.
- **Частота:** редкий edge case — bapm сам якоря не пишет, а типовые манифесты APM обходятся без них.
- **Обходной путь:** развернуть якоря в обычные значения и пересохранить файл без `&` / `*`; после этого bapm читает его штатно.

Воспроизведение:

```bash
repo=$PWD
tmp=$(mktemp -d)
cat > "$tmp/bapm.yml" <<'YAML'
name: anchor-demo
version: 0.0.1
x-base: &base
  enabled: true
x-copy: *base
dependencies:
  apm: []
YAML
(cd "$tmp" && node "$repo/packages/cli/dist/cli.mjs" install)
```

Ожидание: файл отвергнут, код выхода 1.  
Факт: `bapm: YAML anchor (&base) is not allowed (OpenAPM safe subset)`; воспроизведено 08.11.2026.

## Вариации

1. Принять якоря как APM — lock/манифест от APM заработает, но bapm отступит от `req-mf-020` и расширит поверхность парсера.
2. Отвергать как OpenAPM (текущий выбор); **рекомендуется** — fail-closed и соответствие спеке.
3. Разыменовывать якоря при чтении и писать без них — не сделано: требует бюджета раскрытия и меняет round-trip.

## Рекомендация

Оставить вариант 2. Это осознанная строгость OpenAPM, а не баг; код и тесты уже на месте. Оценка S: улучшить диагностику — показывать путь к файлу и, если возможно, позицию якоря, затем закрыть карточку.

Критерии закрытия:

- [ ] вариант 2 подтверждён владельцем;
- [ ] сообщение об ошибке называет файл, а не только текст якоря;
- [ ] тесты манифеста и lock на anchor/alias остаются зелёными.

## Поведение сейчас

Манифест или lock с якорем, алиасом или кастомным тегом не загрузится: команда завершается кодом 1 и сообщением вида `YAML anchor (&base) is not allowed (OpenAPM safe subset)`. bapm сам якоря не пишет; после удаления `&` / `*` файл читается без других изменений.
