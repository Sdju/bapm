# Frozen не ловит смену `#ref`

**Статус:** открыто  
**Класс:** продукт / дыра в CI-гейте

## Суть

Frozen проверяет: lock есть, у каждой прямой зависимости есть пин, развёрнутые файлы совпадают с хешами. Если в манифесте у уже закреплённого пакета поменяли `#v1` на `#v2`, а lock не трогали, frozen install ставит старый коммит из lock и выходит 0.

## Состояние

| Источник     | Позиция                                                                                               |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| APM          | Frozen/lock gate в первую очередь про пины и дерево, не про дрейф constraint у уже записанной строки. |
| OpenAPM      | lk-018 / frozen: lock присутствует, пины прямых, integrity. Сверка constraint↔pin — отдельный вопрос. |
| Спека bapm   | Frozen + CI-default; `--update` с frozen запрещён.                                                    |
| Код bapm     | `Install/frozen.ts` + pin presence. Constraint/ref манифеста с `resolved_ref` не сравнивается.        |
| Документация | `guide/situations/ci-frozen.md` warning «Что frozen не ловит».                                        |

## Вариации

1. Считать расхождение `#ref` и pin ошибкой frozen (как «забыли обновить lock»).
2. Игнорировать (текущее) — ловится только ревью / `outdated`.
3. Отдельная проверка в `audit --ci` — сейчас её нет.

## Поведение сейчас

`CI=1 bapm install` и `bapm install --frozen` проходят. Ставится `resolved_commit` из lock. Чтобы сменить ref, нужен обычный (не frozen) `install` или `update` вне CI.
