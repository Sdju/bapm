# Корневые `targets` молча сужают раскладку

**Статус:** намеренно (правило) / открыто (UX)  
**Класс:** продукт

## Суть

`target` / `targets` в корне манифеста — это не «какие агенты активны», а «на каких агентов вообще разрешено класть файлы». `active` и `--target` выбирают хост, но intersection отбрасывает всех, кого нет в объявленном списке. Сообщение выглядит как успех.

## Состояние

| Источник       | Позиция                                                                                                                             |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| APM            | Предпочтение хоста ближе к одному полю; intersection в том же виде не выделен.                                                      |
| OpenAPM tg-008 | Нельзя одновременно `target` и `targets`. Intersection active ∩ declared ∩ package targets.                                         |
| Спека bapm     | `install-pipeline`: `active` не расширяет declared ids. Change `sync-specs-with-shipped-behavior` добавляет явный сценарий сужения. |
| Код bapm       | `runInstall.ts`: если есть declared ids и активного нет в списке — примитивы пакета не деплоятся.                                   |
| Документация   | `guide/host-selection.md` warning; вывод `installed for <id>` без файлов.                                                           |

## Вариации

1. Считать `targets` только регистрацией интеграций, не фильтром (ломает OpenAPM).
2. Фильтровать и падать, если active не пересекается с declared.
3. Фильтровать и печатать успех (текущее) — пользователь видит «installed for claude» и пустой `.claude/`.

## Поведение сейчас

`targets: { cursor: "@b-apm/integration-cursor" }` + `--target claude` (claude зарегистрирован каноническим пакетом) не кладёт файлы в Claude. Карта `targets` ещё и регистрирует пакеты интеграций. См. [init-target-writes-targets.md](./init-target-writes-targets.md).
