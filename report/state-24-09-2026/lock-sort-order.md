# Порядок записей в lock

**Статус:** намеренно  
**Класс:** намеренное отличие

## Суть

Один и тот же набор зависимостей APM и bapm записывают в lock в разном порядке. Содержимое пинов может совпадать, diff lock-файла — нет.

## Состояние

| Источник     | Позиция                                                                            |
| ------------ | ---------------------------------------------------------------------------------- |
| APM          | Сортировка по глубине в дереве разрешения.                                         |
| OpenAPM      | Стабильный порядок по идентификатору пакета (`repo_url`, затем `virtual_path`).    |
| Спека bapm   | Lock serialize MUST сортировать по `(repo_url, virtual_path)`.                     |
| Код bapm     | `packages/core/src/modules/Lockfile/serialize.ts` — `localeCompare` по `repo_url`. |
| Документация | `guide/conformance.md` и `CONFORMANCE.md` называют это намеренным отличием.        |

## Вариации

1. Сохранять порядок APM, чтобы `apm` ↔ `bapm` не шумели в git.
2. Порядок OpenAPM (текущий выбор).
3. Не пересортировывать чужой lock, пока пины не менялись — не сделано: любой write канонизирует порядок.

## Поведение сейчас

Каждая запись lock bapm переписывает `dependencies` в порядке `repo_url`. Lock, который принёс `apm`, после `bapm install` может дать большой diff только из-за перестановки.
