# HTTP `headers` MCP не попадают в конфиг агента

**Статус:** открыто  
**Класс:** баг

## Суть

В манифесте у HTTP/SSE сервера можно задать `headers`. Bake их резолвит, collect их не прокидывает, интеграции в конфиг не пишут.

## Состояние

| Источник     | Позиция                                                                                                                                                                                       |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| APM          | HTTP MCP с заголовками (в т.ч. Authorization) поддерживается в конфиге хоста.                                                                                                                 |
| OpenAPM      | `headers` — допустимая часть декларации MCP.                                                                                                                                                  |
| Спека bapm   | `mcp-env-bake` явно печёт и `env`, и `headers`.                                                                                                                                               |
| Код bapm     | `Mcp/collect.ts` `ParsedMcpEntry` не содержит `headers`; `toCollected` их не копирует. `Mcp/bake.ts` умеет печь `headers`, но до bake они уже потеряны. Cursor integration `headers` не ищет. |
| Документация | `guide/manifest-dependencies.md`: «headers … в конфиг агента не передаются вовсе».                                                                                                            |

## Вариации

1. Прокинуть `headers` через collect → bake → configureMcp (как требует bake-спека).
2. Оставить drop и требовать ручную настройку в агенте (текущее).
3. Печь headers только в lock — lock их тоже не сохранит, если collect их выкинул.

## Поведение сейчас

`headers` в `dependencies.mcp` игнорируются. Если серверу нужен заголовок авторизации, его надо прописать в агенте вручную. Значения из `${VAR}` в headers не подставляются, потому что поле не доходит до bake.
