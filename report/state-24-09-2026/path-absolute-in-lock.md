# `path:` пишется в lock абсолютным путём

**Статус:** открыто  
**Класс:** баг / переносимость

## Суть

Общий `path: ./tools/team-skills` должен работать у всей команды. В lock bapm кладёт абсолютный путь машины, которая сделала install. На другой машине тот же lock врёт или падает.

## Состояние

| Источник     | Позиция                                                                                        |
| ------------ | ---------------------------------------------------------------------------------------------- |
| APM          | Локальный path в lock обычно канонизируется относительно проекта или остаётся как в манифесте. |
| OpenAPM      | Identity path — переносимый идентификатор, не путь CI-агента.                                  |
| Спека bapm   | `path:` — shared source; `local:` — личный.                                                    |
| Код bapm     | Resolve записывает абсолютный путь в `repo_url` / identity.                                    |
| Документация | `guide/manifest-dependencies.md`: «в текущей версии в lock записывается абсолютный путь».      |

## Вариации

1. Писать путь относительно корня проекта.
2. Писать абсолютный (текущее) — lock не шарится.
3. Как `local`: вынести в `bapm.local.lock.yaml` — тогда это уже не командные `path:`.

## Поведение сейчас

`bapm.lock.yaml` содержит что-то вроде `/home/alice/proj/tools/team-skills`. У Bob и в CI путь другой. Для черновиков, которых нет у команды, документация советует `local`, не `path:`.
