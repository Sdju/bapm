# `audit` и `audit --ci` — одно поведение

**Статус:** открыто  
**Класс:** незавершённый флаг

## Суть

В APM `audit --ci` — отдельный гейт для скриптов (lock есть, пины, хеши). В bapm help требует `--ci`, а код вызывает тот же `runAuditCi` и при голом `audit`: `ci: parsed.ci || true`.

## Состояние

| Источник     | Позиция                                                                                                                 |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| APM          | `apm audit` — отчёт; `apm audit --ci` — ненулевой exit, если lock/integrity не сходятся. Скрипты CI завязаны на `--ci`. |
| OpenAPM      | Integrity/lk-015/017 — проверки, не обязательно два режима CLI.                                                         |
| Спека bapm   | Audit CI gate: lock present + deployed presence + hash re-verify.                                                       |
| Код bapm     | `packages/cli/src/modules/Audit/services/runAudit.ts`: `ci: parsed.ci \|\| true`. Флаг парсится, на проверки не влияет. |
| Документация | `reference/audit.md`: «сейчас без флага то же самое, но в скриптах указывайте `--ci`, как в APM».                       |

## Вариации

1. Как APM: без `--ci` мягкий отчёт / другой набор проверок; с `--ci` — жёсткий гейт.
2. Всегда жёсткий гейт, `--ci` оставить для паритета скриптов (текущее).
3. Убрать `--ci` — сломает копипасту из APM.

## Поведение сейчас

`bapm audit` и `bapm audit --ci` проверяют одно и то же. `-o` пишет файл только для json/sarif; text всегда в stdout. Имеет смысл держать `--ci` в CI, чтобы не разъехаться, если режимы когда-нибудь разделят.
