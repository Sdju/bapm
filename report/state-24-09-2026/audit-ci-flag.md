# `audit` и `audit --ci` — одно поведение

**Статус:** намеренно (решение принято: один режим; остаётся честный help)  
**Класс:** незавершённый флаг  
**Важность:** низкая — поведение осознанно выбрано и не ломает проверки; остаётся только расхождение с ожиданием «`--ci` включает отдельный гейт» и подсказкой help.  
**Проверено:** 08-11-2026, working tree

## Суть

В APM `apm audit` — отчёт, а `apm audit --ci` — жёсткий гейт для скриптов: ненулевой exit, если нет lock, пинов или расходятся хеши. В bapm оба вызова идут в один `runAuditCi`, а флаг принудительно превращается в `true`: `ci: parsed.ci || true` (`packages/cli/src/modules/Audit/services/runAudit.ts:171`). Поэтому `--ci` ничего не переключает.

Help при этом описывает `--ci` как «CI gate: lock present + deployed presence + hash re-verify» (`runAudit.ts:132`), а `reference/audit.md` советует указывать флаг в скриптах «как в APM». Пользователь, переносящий пайплайн из APM, получает более строгий `audit` без флага и не получает более мягкого отчёта с флагом. Для bapm это осознанный выбор: один набор проверок проще не разъезжать с CI.

## Влияние

- **Сценарий:** перенос скрипта `apm audit > report.txt` (без `--ci`) в bapm; локальный запуск на неполном lock.
- **Кого задевает:** команды, мигрирующие с APM; авторы CI-шаблонов.
- **Последствие:** голый `bapm audit` завершается кодом 1 там, где APM печатал отчёт и выходил 0. Флаг `--ci` создаёт ложное впечатление, что он добавляет гейт.
- **Частота:** каждый запуск audit в скриптах и локально на неполном дереве.
- **Обходной путь:** трактовать `bapm audit` как всегда-гейт; для «мягкого» отчёта смотреть `-f json`/`-f sarif` и игнорировать код выхода в обёртке.

| Источник     | Позиция                                                                                                                 |

| OpenAPM      | Integrity/lk-015/017 — проверки, не обязательно два режима CLI.                                                         |
| Спека bapm   | Audit CI gate: lock present + deployed presence + hash re-verify.                                                       |
| Код bapm     | `packages/cli/src/modules/Audit/services/runAudit.ts`: `ci: parsed.ci \|\| true`. Флаг парсится, на проверки не влияет. |
| Документация | `reference/audit.md`: «сейчас без флага то же самое, но в скриптах указывайте `--ci`, как в APM».                       |

## Проверка

| Артефакт | Где смотреть |
| -------- | ------------ |
| Код      | `packages/cli/src/modules/Audit/services/runAudit.ts:171` — `ci` всегда `true`. |
| Help     | `packages/cli/src/modules/Audit/services/runAudit.ts:132` — `--ci` описан как отдельный гейт. |
| Тесты    | `packages/cli/tests/audit/format-flags.test.ts`, `integrity-formats.test.ts` — проверяют форматы и integrity, не различие режимов. |
| Спека    | `openspec/specs/audit-integrity/spec.md`, `audit-output-formats/spec.md` — гейт и форматы, без двух режимов. |
| Docs     | `apps/docs/reference/audit.md` — честно фиксирует одинаковое поведение. |

Воспроизведение:

```bash
mkdir /tmp/bapm-audit && cd /tmp/bapm-audit
printf 'name: demo\nversion: 0.1.0\n' > bapm.yml
bapm audit >/tmp/a1 2>&1; echo "plain=$?"
bapm audit --ci >/tmp/a2 2>&1; echo "ci=$?"
diff /tmp/a1 /tmp/a2
```

Ожидание (как в APM): режимы различаются кодом выхода или набором проверок.  
Факт: `plain=1`, `ci=1`, вывод идентичен; сообщение `lockfile missing / not found`.

## Вариации

1. Как APM: без `--ci` мягкий отчёт / другой набор проверок; с `--ci` — жёсткий гейт. Требует нового режима и ломает текущие скрипты, которые рассчитывают на гейт без флага.
2. Всегда жёсткий гейт, `--ci` оставить для паритета скриптов (текущее). - выбрао
3. Убрать `--ci` — сломает копипасту из APM.

## Рекомендация

Оставить вариант 2 и закрыть карточку как «намеренно». Практическое действие — убрать из help формулировку, обещающую отдельный гейт, и явно сказать: «`--ci` принимается для совместимости; проверки всегда включены». Это S: правка help и `reference/audit.md`.

Критерии закрытия:

- [ ] Help и `reference/audit.md` не обещают отдельный режим.
- [ ] Есть тест, фиксирующий одинаковый exit code с флагом и без.
- [ ] В `CONFORMANCE.md`/ограничениях отмечено отличие от APM.

## Поведение сейчас

`bapm audit` и `bapm audit --ci` проверяют одно и то же. `-o` пишет файл только для `json`/`sarif`; `text` всегда идёт в stdout. Имеет смысл держать `--ci` в CI, чтобы не разъехаться, если режимы когда-нибудь разделят.
