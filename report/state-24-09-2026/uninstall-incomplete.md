# `uninstall` частичный и сравнивает по подстроке

**Статус:** открыто  
**Класс:** баг

## Суть

Help обещает убрать пакет из манифеста, modules, deploy и lock. Для git это часто не так. Имя ищется через `includes`, короткое имя задевает несколько пакетов.

## Состояние

| Источник     | Позиция                                                                                                                                                                     |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| APM          | `apm uninstall <name>` убирает запись из манифеста и lock по идентичности пакета.                                                                                           |
| OpenAPM      | Lifecycle uninstall — полное снятие прямой зависимости.                                                                                                                     |
| Спека bapm   | `lifecycle-uninstall-prune`: снять named packages из manifest + modules + deploy + lock.                                                                                    |
| Код bapm     | `Uninstall/runUninstall.ts`: `n.includes(name)`, `repo.includes(name)`, взаимное `r.includes(n)` в `filterApm`. `entryName` для git — последний сегмент URL, не полный URL. |
| Документация | `reference/uninstall.md` warning: git, `path:`/`local`, подстрока.                                                                                                          |

## Вариации

1. Точное совпадение по `name` / каноническому `repo_url` / alias.
2. Подстрока (текущее) — `bapm uninstall skill` может снять несколько пакетов.
3. Принимать полный git URL — сейчас URL «не найден».

## Поведение сейчас

- **git:** по короткому имени запись может уйти из lock и с диска, но сравнение с манифестом слабое; полный URL не распознаётся. Каталог в `apm_modules/<commit>` может остаться, если имя не совпало с cache identity.
- **`path:` и `local`:** команда может завершиться успешно и ничего не снять (нет совпадения `entryName` / lock name).
- Надёжный обход: править `bapm.yml` руками, затем `uninstall` / `prune`.
