# `deps why --json`: `is_direct` по пустому `resolved_by`

**Статус:** открыто  
**Класс:** баг

## Суть

JSON `deps why` помечает пакет прямым, если `resolved_by` пустой или отсутствует. Прямота из манифеста / `depth` не берётся. Запись без `resolved_by` (старый lock, path, сбой записи) выглядит как direct.

## Состояние

| Источник     | Позиция                                                                             |
| ------------ | ----------------------------------------------------------------------------------- |
| APM          | `why` отличает direct по манифесту / depth 1.                                       |
| OpenAPM      | `resolved_by` — цепочка родителей; пусто у корня.                                   |
| Спека bapm   | Why JSON: `is_direct` отражает прямую зависимость.                                  |
| Код bapm     | `Deps/whyDeps.ts` `isDirect`: `by == null` → `true`; пустой массив/строка → `true`. |
| Документация | Не предупреждает о ложных direct.                                                   |

## Вариации

1. Считать direct только depth 1 / имя есть в `dependencies.apm`.
2. Эвристика `resolved_by` (текущее).
3. Поле optional, если данных мало — не сделано.

## Поведение сейчас

Тесты ждут `is_direct: true` у пакетов без родителей. Транзитив с незаполненным `resolved_by` тоже получит `true`. Для скриптов поле нельзя считать надёжным.
