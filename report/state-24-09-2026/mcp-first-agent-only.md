# MCP пишется только первому агенту

**Статус:** открыто  
**Класс:** баг / незавершённый multi-agent

## Суть

`active: { target: [cursor, claude] }` раскладывает skills/rules на каждого, но MCP-конфиг получает только первый id в списке.

## Состояние

| Источник     | Позиция                                                                                                                           |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| APM          | Исторически один активный хост за запуск; multi-agent не тот же контракт.                                                         |
| OpenAPM      | Deploy MCP в рамках активного target; несколько активных — не зафиксировано как MUST на каждый.                                   |
| Спека bapm   | Install оркестрирует несколько active targets для materialize; MCP-контур в `runInstall` обрывается после первой успешной записи. |
| Код bapm     | `packages/core/src/modules/Install/runInstall.ts` около строки 999: после `configureMcp` — `break`.                               |
| Документация | `guide/host-selection.md`, `reference/install.md`, `guide/conformance.md`.                                                        |

## Вариации

1. Писать MCP каждому активному агенту, который его поддерживает.
2. Писать только явно выбранному (`--target`) — тогда multi-`active` для MCP бессмыслен.
3. Только первому (текущее) — файлы есть у всех, серверы — у одного.

## Поведение сейчас

Порядок active: `--target` (один id) → overlay `active` → base `active` → detect. Для списка MCP вызывается `configureMcp` и цикл останавливается. Второй агент в выводе может быть `installed for <id>` без серверов. `--exclude` фильтрует configure, но не отменяет `break`.
