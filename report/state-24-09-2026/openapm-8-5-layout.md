# OpenAPM §8.5 — раскладка файлов по агентам

**Статус:** намеренно (не заявлено)  
**Класс:** намеренное отличие

## Суть

OpenAPM описывает единую раскладку примитивов по хостам. bapm раскладывает файлы так, как решит пакет `@b-apm/integration-*`. Это не проверяется фикстурами §8.5.

## Состояние

| Источник     | Позиция                                                                              |
| ------------ | ------------------------------------------------------------------------------------ |
| APM          | Свой набор путей (исторически cursor-first, плюс другие адаптеры в Python).          |
| OpenAPM §8.5 | Каноническая per-target раскладка.                                                   |
| Спека bapm   | Чеклист `req-tg-002…010`: «§8.5 per-target layout not verified».                     |
| Код bapm     | Каждая интеграция задаёт свои `deployRoots` и пути (см. `guide/supported-hosts.md`). |
| Документация | `guide/conformance.md`: «требования 8.5 пока не проверяются».                        |

## Вариации

1. Заявить §8.5 и подогнать все интеграции — большая ломка путей.
2. Не заявлять (текущий выбор): пользовательская таблица путей — источник правды.
3. Заявить §8.5 только для одного хоста — в `CONFORMANCE.md` всё ещё торчит формулировка «beyond cursor», см. [conformance-beyond-cursor.md](./conformance-beyond-cursor.md).

## Поведение сейчас

Skills Cursor лежат в `.agents/skills/`, Claude — в `.claude/skills/`, OpenCode — в `.opencode/skills/` и т. д. Совпадение с §8.5 не гарантируется и не тестируется.
