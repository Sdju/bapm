# OpenAPM §8.5 — раскладка файлов по агентам

**Статус:** намеренно (не заявлено)  
**Класс:** намеренное отличие  
**Важность:** низкая — ограничение честно заявлено и покрыто пользовательской таблицей путей; ломается только ожидание канонической раскладки OpenAPM, данных не теряется.  
**Проверено:** 08-11-2026, working tree

## Суть

OpenAPM §8.5 описывает единую каноническую раскладку примитивов по хостам: для каждого target задано, куда попадают skills, rules, MCP и остальные типы файлов. bapm эту раскладку не заявляет. Файлы раскладывает пакет `@b-apm/integration-*`: каждая интеграция сама задаёт `deployRoots` и конкретные пути, а core только передаёт ей materialize-контекст.

Из этого следует, что совпадение с §8.5 не гарантируется и не проверяется. В чеклисте требования `req-tg-002`, `003`, `005–010` (разделы 8.5 / 8.5.x) стоят в статусе `skipped` с одним rationale: «per-target layout not verified». Это не скрытый pass: `CONFORMANCE.md:36` прямо говорит, что §8.5 не заявлен, а раскладка определена пакетами интеграций.

Отдельно стоит `req-tg-001` (§8.4): он `active` и покрывает materialize через `target-materialize.test.ts` / `cursor-e2e.test.ts`. То есть базовый per-target deploy проверяется, а именно каноническая карта путей §8.5 — нет. `req-tg-004` относится к §4.2.1, а не к §8.5, поэтому в диапазон «002…010» не входит.

Формулировка «multi-target adapters beyond cursor» из старых limitations в текущем `CONFORMANCE.md` уже снята: осталась нейтральная строка «§8.5 per-target layout is not claimed». Смежная карточка про эту формулировку — [conformance-beyond-cursor.md](./conformance-beyond-cursor.md).

## Влияние

- **Сценарий:** команда переходит с APM и ожидает, что skills для Cursor окажутся по пути из §8.5, а не в `.agents/skills/`.
- **Кого задевает:** мигрирующие пользователи, авторы интеграций, CI-проверки, ищущие файлы по каноническому пути.
- **Последствие:** файлы лежат в другом месте, чем обещает §8.5; инструмент, завязанный на каноническую карту, их не найдёт. Сами файлы записаны корректно.
- **Частота:** каждый install для хостов, чья раскладка отличается от §8.5; насколько именно — не измерено, фикстур нет.
- **Обходной путь:** сверяться с таблицей `apps/docs/guide/supported-hosts.md:31-44`; это фактический контракт bapm.

## Вариации

1. Заявить §8.5 и подогнать все интеграции — большая ломка путей и публичного контракта пакетов.
2. Не заявлять (текущий выбор); **рекомендуется** — пользовательская таблица путей остаётся источником правды, ограничение честно описано.
3. Заявить §8.5 только для одного хоста — появится частичная политика и отдельная матрица фикстур; формулировка «beyond cursor» в `CONFORMANCE.md` уже снята, см. [conformance-beyond-cursor.md](./conformance-beyond-cursor.md).

## Рекомендация

Оставить вариант 2. Это осознанный отказ от невыполнимого обещания, а не баг; docs и чеклист согласованы. Оценка S: закрыть карточку как намеренное ограничение и не добавлять §8.5-фикстуры без отдельного решения о смене раскладки.

Критерии закрытия:

- [ ] вариант 2 подтверждён владельцем;
- [ ] в `CONFORMANCE.md` и чеклисте нет формулировки «beyond cursor» и нет `active` для §8.5;
- [ ] `supported-hosts.md` остаётся актуальной таблицей путей.

## Поведение сейчас

Skills Cursor лежат в `.agents/skills/`, Claude — в `.claude/skills/`, OpenCode — в `.opencode/skills/` и т. д.; полная таблица — в `supported-hosts.md`. Совпадение с §8.5 не гарантируется и не тестируется. Пользователь не видит предупреждения при install: документация заранее говорит, что каноническая раскладка OpenAPM не заявлена.
